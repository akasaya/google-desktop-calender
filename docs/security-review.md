# セキュリティ点検記録

実施日: 2026-10-06。対象: 公開Gitリポジトリ、Python/Qtアプリ、Windows配布とインストール処理。
開発時の基準は [SECURITY.md](../SECURITY.md) にまとめています。

## 結論と範囲

点検時点で、Git履歴への認証情報混入や既知の依存脆弱性は検出しませんでした。
ただし、Windows認証の平文保存とCIの保護機能などに改善点があり、修正しました。
これはソースレビューと自動検査による確認であり、安全性の認証や侵入試験の合格を意味しません。

## 発見した改善点

| 対象 | 点検時の状態 | 対応 |
| --- | --- | --- |
| Windowsの認証ファイル | ユーザーフォルダ内の平文JSON | ユーザー単位のDPAPIで暗号化。旧形式は初回読み込みで原子的に移行。失敗時に平文へ戻さない |
| OAuth設定JSON | 指定された認証・トークンURLをそのまま使用 | Google公式の完全一致URLのみ許可 |
| 外部リンク | HTTPSであれば表示可能 | Googleカレンダーのホストとパスに限定。スキーム・ポート・ユーザー情報・制御文字も検査 |
| GitHub Actions | バージョンタグで参照 | 公式リポジトリのコミットSHAへ固定。チェックアウトの資格情報を残さない |
| 公開リポジトリの保護機能 | 秘密情報スキャン等が無効 | Secret scanning、push protection、Dependabotアラート/修正、非公開脆弱性報告を有効化してAPIで確認 |
| 継続検査 | 一般テストのみ | Securityワークフローをpush・PR・週次で実行 |
| 配布ファイル | チェックサムなし | ビルド時にSHA256SUMS.txtを生成 |

## 確認したこと

- 監査開始時の全59件のロック済みレジストリ依存を、OS条件を無視してpip-auditで照合。既知脆弱性・照合スキップともに0件。
- Git履歴を秘密情報パターンで検査し、認証ファイルが追跡されていないことを確認。ユーザーの設定フォルダはGit・ビルド対象外。
- 変更前のWindows exe（ソース `808054d`）のPyInstallerアーカイブ861項目を検査。認証ファイル名の混入なし。
- Banditの検査を実施。固定コマンドのシェルなし呼び出しと公開エンドポイントについて、誤検出の理由を対象行へ記載。その他の指摘なし。
- 新規認証は `calendar.readonly`、外部ブラウザ、ループバックIP、PKCE S256とstateを使用。
- API操作は予定のGETのみ。証明書検証の無効化、予定本文のファイル保存、分析サービスへの送信なし。
- 予定タイトル・場所はQtのPlainText。未検証のURLやHTMLをそのまま実行しない。

## 残る制約

- exeはコード署名していません。SHA-256は破損・差し替えの比較材料であり、発行者の署名ではありません。
- DPAPIは同じWindowsユーザーとして動作するマルウェアや管理者からの保護ではありません。Linux/WSLの認証は権限600による保護で、暗号化していません。
- 既存MCP認証の明示インポートでは、元のGoogle権限が読み取り専用より広い可能性があります。新規の読み取り専用認証を推奨します。
- 脆弱性DB未登録の問題、Qtのネイティブ部分を含む全バイナリの侵入試験、Windowsの他ユーザーによる攻撃試験、Google Cloudの管理設定全体は対象外です。
- 文字列パターン検査は、難読化された秘密情報や画像内の情報を完全には検出できません。同梱画像はデモ予定であることを目視確認済みです。
- Gitの作者情報にはGitHub noreply形式ではないメールアドレスが含まれ、公開されています。認証情報ではありませんが、公開したくない場合は今後の作者設定をnoreplyへ変更し、過去履歴は別途扱う必要があります。今回、作者情報の変更・共有履歴の書き換えは行っていません。
- Googleアカウントの二要素認証、OSの更新・ディスク暗号化、配布元アカウントの保護は別途管理する必要があります。

## 最終確認

- Linux: 49件成功、Windows専用1件はskip。Windows: 50件成功。
- [Security CI](https://github.com/akasaya/google-desktop-calender/actions/runs/37343561135)、[通常CI](https://github.com/akasaya/google-desktop-calender/actions/runs/37343561160)、[Windows exeビルド](https://github.com/akasaya/google-desktop-calender/actions/runs/37343560919)は成功。

- 最終exeの同梱861項目に認証ファイル名の混入なし。ダウンロードしたexeとCI生成SHA-256が一致。
- Windows実機で既存の平文認証をDPAPI形式へ移行し、平文のトークン項目が保存されていないことを確認。
- 別プロセスで暗号化済み認証を再読み込みして、実予定の取得・画面表示に成功。予定本文は記録していません。
- 認証ファイルにEveryone / Authenticated Users / Usersグループへの許可がないことを確認。
- Linux側の設定ディレクトリ700・トークン600、および利用中のGoogle権限が読み取り専用のみであることを確認。
- Windows Authenticodeの状態は `NotSigned`。配布元を暗号学的に証明する署名は未対応。
